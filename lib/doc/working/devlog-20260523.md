## 3. 설계 메모

### structured output — tool-use 강제

Anthropic Messages API 는 OpenAI 의 `text.format.json_schema` / Gemini 의
`responseSchema` 같은 네이티브 구조화 응답 필드가 없다. 따라서:

1. `ResponseSchema` 를 단일 tool 의 `input_schema` 로 등록
2. `tool_choice: {type:"tool", name:<schemaName>}` 로 해당 tool 호출을 강제
3. 응답의 강제된 `tool_use` 블록 `input` 을 JSON 문자열로 반환

`ClaudeChatting.sendPromptWithSchema` 의 반환 포맷 (`message` / `structured`) 은
OpenAI/Gemini 경로와 동일하게 유지 — 호출자 코드 변경 불필요.

### tool use — content block 매핑

- assistant `tool_use` content 블록 ↔ 다음 user 메시지의 `tool_result` 블록
- 한 turn 의 모든 tool_result 는 **단일 user 메시지**에 묶어야 함 (Gemini 와 유사, OpenAI 와 상이)
- `ToolResult.callId` → `tool_result.tool_use_id` 직결 (Gemini 처럼 이름 추정 불필요)

### anthropic-version

`ClaudeAPIConnection.DEFAULT_ANTHROPIC_VERSION = "2023-06-01"` 상수 기본값 +
3-arg 생성자로 override. demo 는 `CLAUDE_API_VERSION` properties (빈 값이면 기본값) 로 주입.

### cost — 캐시 토큰

Anthropic `usage.input_tokens` 는 캐시 토큰 미포함, `cache_creation_input_tokens` /
`cache_read_input_tokens` 별도 보고. `CostTable` 은 단일 input 단가만 가지므로
캐시 토큰을 input 에 합산 (cache_read 는 실제 더 저렴해 약간 과다 계상 — 근사 허용).

```
HTTP 400 invalid_request_error
"Your credit balance is too low to access the Anthropic API."
request_id: req_011CbJ68fAFrNWAjLP1UrwNQ
```

→ DNS/TLS 연결, `x-api-key` 인증 처리, `anthropic-version` 헤더, 요청 본문 형식
모두 정상 통과 확인 (400 은 빌링 게이트일 뿐 — 키 무효 시 401 `authentication_error`).
점검용 임시 테스트는 검증 후 삭제.
